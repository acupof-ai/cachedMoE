================================

打开： http://127.0.0.1:8080/

镜像（第二个读源）：**关**。Track D4（docs/p4_dual_source.md §8、STATUS §3 的 60）
是第三次判 NO-GO —— 这一次 E: **通过了为它写的那道验收门**
（DX §5.1：48 句柄 × QD 24，两条 300 秒臂各 1.04 GB/s、零错误，句柄 158 ms），
**引擎照样死在同一个 tensor、同一个偏移**：
`pinned load of 'norm.weight': overlapped read failed (win32 1117, 12288 B at off 1323827200)`，
摘源时的码是 **win32 433 = ERROR_NO_SUCH_DEVICE**（盘不在总线上了）。
所以下面的命令**不带 `--mirror`**，和 main 的默认行为逐字相同。

ℹ️ `server.py` 现在**有** `--mirror DIR` 透传了（Track D4；之前文档说有、其实没有），
并且引擎侧有了镜像健康闸：启动时从镜像试读 pinned 权重、失败就摘镜像单盘跑，
运行期连续 3 次 I/O 错误也动态摘源。**闸能让镜像不再是致命的，但它救不了这块 U 盘**
（pinned load 的第一个失败请求仍然会被抛出去）。
**这块 U 盘不要再试** —— 包括在它通过了那道门之后。

    -RedirectStandardOutput C:\Users\Asus\code\deepmoe\build\web_ui.out `

✅ **`--cache-slots` 已经不用给了**（Track H1a 生效，本实例就是这样起的）：

并且建完 slab 池先提交一个空命令缓冲探一下，被拒就退 200 槽重建（最多 5 次）。
本次就绪横幅：`expert cache 87.6 GiB (5000 slots)`。

  ✅ **不用再在重启前清空了**（Track H1b，本实例的 exe 已经带上）：`.pkv` 恢复失败——
  分配被拒 / 损坏 / 尺寸不符，任何错误码——现在是一条 warning + 冷 prefill，
  那一轮照常跑完，失败的那份 `.pkv` 自己被删掉。见 docs/p4_kv_ux.md §5.2。

  它以前是致命的：默认 cache 大小下 path A 会被 expert cache 占满
  （`slab pool: path A full after 34 slabs`），恢复拿不到显存就报
  `serve: kv-disk restore failed: internal: vkQueueSubmit2 failed (-2)`，
  而这个错误**直接杀掉那一轮对话**（抛进 tools/chat.py:186）。

  注意「不致命」不等于「能恢复」：path A 满时恢复仍然拿不到显存，
  那一轮付完整 prefill（STATUS §7 第 2 项的 ②）。要手动清的话还是这一行：

      Remove-Item "$env:LOCALAPPDATA\deepmoe\kv\D__models_DeepSeek-V4.1-Flash\*.pkv"
