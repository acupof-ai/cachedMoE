deepMoE web UI —— 正在运行的实例
================================

打开： http://127.0.0.1:8080/

镜像（第二个读源）：**关**。Track D3（docs/p4_dual_source.md §7、STATUS §3 的 59）
判了 NO-GO —— 带 `--mirror E:\...` 时引擎**连初始化都过不去**
（`pinned load of 'norm.weight': overlapped read failed`，win32 1117 = ERROR_IO_DEVICE）。
所以下面的命令**不带 `--mirror`**，和 main 的默认行为逐字相同。

启动命令（已用 Start-Process 脱离本会话，关掉终端也不会停）：

  $env:DEEPMOE_MODEL_DIR = 'D:\models\DeepSeek-V4.1-Flash'
  Start-Process -FilePath C:\Users\Asus\code\deepmoe\.venv\Scripts\python.exe `
    -ArgumentList C:\Users\Asus\code\deepmoe\tools\web\server.py,
                  --exe,C:\Users\Asus\code\deepmoe\build\deepmoe.exe,
                  --max-context,524280,--port,8080,--cache-slots,5000,
                  --log,C:\Users\Asus\code\deepmoe\build\web_serve.log `
    -WorkingDirectory C:\Users\Asus\code\deepmoe -WindowStyle Hidden `
    -RedirectStandardOutput C:\Users\Asus\code\deepmoe\build\web_ui.out `
    -RedirectStandardError  C:\Users\Asus\code\deepmoe\build\web_ui.err

⚠️ `--cache-slots 5000` 对**正在跑的这个实例**仍然是必须的。
不给它就是 `auto` = 5,100 槽，而 5,100 在这台机器上**第一个 decode submit 就死**
（`vkQueueSubmit2 failed (-2)` = VK_ERROR_OUT_OF_DEVICE_MEMORY，slab 布局 34 A + 17 B）。
5,000 槽是 34 A + 16 B，干净。见 STATUS §1「cache 容量上限」与 §3 的 59。

✅ **下一次重启可以不再给它**（Track H1a，分支 `p4/h1-defaults`）：`auto` 现在
① 封顶到 5,000 槽（`DEEPMOE_CACHE_SLOT_CAP` 可改，0 = 关），并且
② 建完 slab 池**先提交一个空命令缓冲探一下**，被拒就退 200 槽重建（最多 5 次，
`DEEPMOE_CACHE_BACKOFF_SLOTS`）。丢设备时不重试，直接报「下一次用 --cache-slots N-200」。

⚠️ **两个前提，缺一不可**：
  1. **必须先重新链接 `build\deepmoe.exe`**——正在跑的这个 exe 是改动之前的，
     旧 exe 里 `auto` 还是 5,100，去掉 `--cache-slots` 会当场死。
  2. **必须重启网页 UI**（停掉下面那三个 PID 再按上面的命令起），
     serve 的缓存大小只在启动时决定。
  在这两件做完之前，命令里的 `--cache-slots 5000` **不要删**。
  并且 H1a 本身**还没在 GPU 上验过**（STATUS §6 的 14）——第一次不带 `--cache-slots`
  重启时，看一眼 `build\web_serve.log` 里的 `engine: cache probe passed at N slots`。

.pkv 前缀 KV 缓存
-----------------
  目录  %LOCALAPPDATA%\deepmoe\kv\D__models_DeepSeek-V4.1-Flash

  ⚠️ **重启前先清空这个目录。** 默认 cache 大小下 path A 会被 expert cache 占满
  （`slab pool: path A full after 34 slabs`），此时 `.pkv` 恢复拿不到显存：

      serve: kv-disk restore failed: internal: vkQueueSubmit2 failed (-2)

  而这个错误**不是降级成 warning，是直接杀掉那一轮对话**（抛进 tools/chat.py:186）。
  一行绕开：

      Remove-Item "$env:LOCALAPPDATA\deepmoe\kv\D__models_DeepSeek-V4.1-Flash\*.pkv"

  本次启动前该目录已清空，所以当前实例不受影响；**下一次重启会踩到**。

  ✅ **已修（Track H1b，同一个分支）**：恢复失败——分配被拒 / 损坏 / 尺寸不符，
  任何错误码——现在是一条 warning + 冷 prefill，那一轮照常跑完，失败的那份 `.pkv` 被删掉。
  见 docs/p4_kv_ux.md §5.2。**同样要求重新链接 exe + 重启网页 UI 才生效**；
  在那之前上面那条 `Remove-Item` 仍然是重启前的必做项。
  注意这只是「不致命」：path A 满时恢复仍然拿不到显存，那一轮付完整 prefill（STATUS §7 第 2 项的 ②）。
