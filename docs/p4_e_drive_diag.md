# Track DX — E: 盘到底坏在哪一层（2026-09-19 晚）

一句话：**不是 SSD，是 USB/UAS 桥。**
`deepmoe` 完全不在场的情况下，**48 个句柄 + QD 24 的 4 MiB 随机读，17 秒就把 E: 打死了**——
同一份负载在 D: 上跑 60 秒、4.53 GB/s、零错误。

出处：`bench/results/dx/`（探针源码、三次 run 的原始输出、48 小时事件日志、设备状态）。
本轮**没有起任何引擎**（`deepmoe serve` pid 46276 是用户的网页 UI，一直没碰），
**没有写过 D:\models**，**没有改过任何系统设置**。

三件要读出来的事：

1. **PDO 名字换过**：12–13 点是 `\Device\00000114`，16 点之后是 `\Device\00000118`，
   设备名到了 **DR3**——**设备被重新枚举过（拔插）**，和 D2 §7 记的「已物理重插」对得上。
2. **`UASPStor 129` 永远走在 `disk 153/154` 前面或同时。**
   129 是 **UAS 驱动对整个端口下的总线复位**，不是对某个坏 LBA 的重试。
   **先是桥不应答，然后才有 IO 失败**——因果方向是从桥到盘，不是从盘到桥。
3. **出错的 LBA 到处都是**：0x64800、0x77218、0x626b20、0xb25a038、0x6c3ba……
   **没有一个 LBA 重复出现**。坏块/坏 NAND 会在**同一片地址**上反复报错，这里没有。
4. **`Ntfs 50` 说 E:\\$Mft 丢过写**：这盘是只读镜像，**唯一的写是 NTFS 自己的元数据**，
   也就是说**连元数据都写不下去**。这是文件系统级的损坏风险，不只是读失败。

## 3. 不带引擎复现：`bench/results/dx/dx_probe.cpp`

引擎那次失败的形状是：**48 个 `FILE_FLAG_NO_BUFFERING|FILE_FLAG_OVERLAPPED` 句柄同时开着**，
一堆 4 MiB 的 expert chunk 在飞，中间夹一个 **12 KiB 的 pinned 权重读**。
探针把这个形状原样搬出来，**一行 deepmoe 代码都不碰**：N 个句柄绑同一个 IOCP，
QD 限流，5 秒打一次吞吐，**第一个错误就停**并打出 win32 码/长度/偏移，
`--stall-s` 秒没有任何完成就判**卡死**。

### 3.1 三次 run

| # | 盘 | 句柄 | QD | 12 KiB 插入 | 时长 | 结果 |
|---|---|---:|---:|---|---:|---|
| 1 | **D:** | 48 | 24 | 无 | 60 s | ✅ **4.526 GB/s**，64,743 次读，**零错误零重试** |
| 2 | **D:** | 48 | 24 | 每 8 个一次 | 30 s | ✅ **4.570 GB/s**，37,340 次读（4,669 个小读），**零错误** |
| 3 | **E:** | 48 | 24 | 无 | 目标 180 s | ❌ **17 秒后掉线**，46 秒放弃 |

### 3.2 E: 那一次的逐秒

```
[E_a_cold] opened 48 handles in 17000 ms          <-- D: 是 1 ms
[E_a_cold] t=  5s  0.769 GB/s  reads= 917  inflight=24
[E_a_cold] t= 10s  0.846 GB/s  reads=1926  inflight=24
[E_a_cold] t= 15s  0.851 GB/s  reads=2940  inflight=24
[E_a_cold] t= 20s  0.105 GB/s  reads=3065  inflight=24   <-- 断崖
[E_a_cold] t= 25s  0.000 GB/s  reads=3065  inflight=24
[E_a_cold] t= 30..45s  0.000 GB/s  reads=3065 inflight=24
[E_a_cold] STOP reason=STALL  NO COMPLETION for 30 s
```

同一时刻的系统日志：

```
19:00:36  disk      153  x33   已在磁盘 1 ... 重试 IO 操作
19:00:52  UASPStor  129        发出了对设备 \Device\RaidPort4 的重置
19:01:42  UASPStor  129        （50 秒后再来一次）
19:02:32  UASPStor  129        （再一次，仍然没回来）
```

**读出来的四件事：**

1. **开 48 个句柄就要 17 秒**（D: 是 1 ms）。还一个字节都没读，桥已经吃不消了。
   这正好解释 D2 §4 第 3 个 cell 那句「卡死在 `48 shards open` 之后」——
   **它不是开完之后才死的，它是在开的过程里就已经在垂死挣扎。**
2. **稳定 0.85 GB/s 跑了 15 秒，然后一刀切到 0。** 不是渐降，不是抖动，是**停止应答**。
3. **24 个请求永远挂在 `inflight`**，一个完成包都不再回来。UAS 驱动每 **50 秒**复位一次端口，
   **复位三次都没救回来**。
4. **`12 KiB` 那个读根本不需要出现。** 纯 4 MiB 就打死了。
   所以 `norm.weight` 那条 `win32 1117` **是受害者不是凶手**——
   它只是碰巧是桥咽气那一刻正在飞的那个请求。D2 §7「同一个 tensor 的第二次复现」
   其实是**同一个启动序列里同一个时间点**，不是同一个地址。

### 3.3 没跑的三个格子（以及为什么）

| 没跑 | 理由 |
|---|---|
| E: 臂 (b)：12 KiB 插入 | 臂 (a) 已经把设备打死；任务书的规矩是**停，不重试** |
| E: 臂 (c)：冷 / 热对比 | 臂 (a) **本身就是冷的**（设备从 16:12 起闲置 2 小时 48 分）。热的那一半要重跑 |
| 运行中的温度曲线 | `Get-StorageReliabilityCounter` 需要管理员，`smartctl` 没装（§2） |

> **E: 现在是掉线状态。需要物理拔插才能再用。** 本轮在 19:00:50 之后没有再碰过它。

## 4. 五个假说的排序

| # | 假说 | 判决 | 证据 |
|---|---|---|---|
| **1** | **RTL9210 桥 / UAS 固件在高并发下锁死** | **极高**（主因） | 129 复位**先于**IO 失败；出错 LBA 全不重复；开 48 句柄 17 秒；同一块盘 1 句柄 QD 8 能稳跑 0.96 GB/s，48 句柄 QD 24 活不过 17 秒；**失败跟负载形状走，不跟地址走** |
| 2 | 总线供电不足（平板口 + 2 TB NVMe 突发） | 中低 | 盒子总线供电、机器在交流上；QD 24 时 SSD 瞬时功耗最高。**但没法证**——读不到功耗，也读不到温度。它与 #1 不互斥：桥掉电和桥锁死在日志里长得一样 |
| 3 | USB 选择性暂停 | 低 | `DeviceSelectiveSuspended=1`、交流直流都启用，**确实是个隐患**；但挂起不可能在 24 个命令在飞的时候发生。它最多解释「第一次访问卡一下」，解释不了稳态崩溃 |
| 4 | 线 / 接口接触 | 低 | 坏线给的是**随机**的 CRC 重试，包括空闲时。这里是**确定性**的：每次同一个形状、十几秒、必死 |
| 5 | **SSD 本身**（坏块 / 控制器） | **最低，但未证伪** | 同一块 NAND 刚吞下 510 GB 持续写、964 MB/s、SHA-256 校验干净（D2 §1）；错误 LBA 不重复；`disk 154` 报的是**传输层**硬件错误。**唯一的窟窿：SMART 没读到**（§2） |

### 4.1 USB4 盒子会改变什么

| 假说 | USB4 盒子 | 说明 |
|---|---|---|
| #1 桥/UAS | ✅ **应该修掉** | USB4/TB 盒子走 **NVMe over PCIe 隧道**，**没有 UAS，没有 SCSI 翻译，没有 RTL9210**。失效的那一层整个消失 |
| #2 供电 | ⚠️ **可能更糟** | USB4 盒子**更耗电**不是更省电，而且盘会从 1 GB/s 提到 3 GB/s+。如果根因是平板端口的供电轨，换盒子只会加压 |
| #3 选择性暂停 | ❌ **不变** | 那是 Windows 的电源设置，和盒子无关 |
| #4 线 | ⚪ 顺带 | USB4 需要认证的 40 Gbps 线，新盒子会带一根 |
| #5 SSD | ❌ **完全不变** | 盘真坏了的话换盒子一点用没有。**所以验收测试必须做** |
| （热） | ⚠️ **风险上升** | 速度翻 3 倍 = 发热翻几倍。新盒子的散热片是否够，得看温度 |

### 4.2 两个**故意没做**的系统改动

* **UAS → BOT（`uaspstor` 降级成 `USBSTOR`，注册表 `HKLM\...\Control\usbflags` / `Device Parameters`）**——
  这是**系统设置**，任务书明令不改。它大概率能让盘**别再掉线**（代价是丢掉 UAS 的队列，带宽掉到一半以下）。
  **要不要做由用户决定。**
* **关掉 USB 选择性暂停**——同样是系统设置，同样没改。
  如果决定继续用 USB 路径，这一条建议顺手关掉（`powercfg`，交流与直流都设 0）。

## 5. USB4 盒子到货之后怎么验

### 5.1 验收门（**通过才算这块盘可用**）

D2 §7.3 已经付过一次学费：**`ls` 过了、`nvme_bench` 单句柄过了，引擎照样死。**
**`ls` 不是健康检查，单句柄 bench 也不是。** 新的门是**引擎的形状**：

```
# 1. 句柄开销：48 个句柄必须在 1 秒内开完（本轮 E: 用了 17 秒）
# 2. 主臂：48 句柄 / QD 24 / 4 MiB 随机 / 300 秒，零错误零 STALL
dx_probe.exe --dir "X:\models\DeepSeek-V4.1-Flash" --handles 48 --qd 24 --secs 300 --label usb4_a
# 3. 小读臂：同上 + 每 8 个插一个 12 KiB
dx_probe.exe --dir "X:\..." --handles 48 --qd 24 --secs 300 --small-every 8 --label usb4_b
# 4. 热臂：紧接着再跑一遍 (2)，不给它冷却
# 5. 对照：同样四条在 D: 上必须全过（本轮 D: 已经过了前两条）
```

三条臂全过，**再**跑 `d2_abab.py`。中间任何一条出 win32 码或 STALL：**停，不重试，报告。**

### 5.2 引擎里应该加的那条闸（**镜像侧健康检查**）

D2 §2 的规矩是「镜像是优化，永远不是正确性输入」，但**现在这条规矩没有覆盖启动**：
`open_mirror` 成功 ≠ 这块盘能用，于是 pinned load 在**镜像上**失败就把整个引擎杀了（D2 §7）。

**建议**（本轮未实现，属于代码改动）：

1. `--mirror` 打开后，**先从镜像做一次 pinned 权重试读**（就是 `norm.weight` 那类 12 KiB 读，
   48 句柄都开着的时候），**这才是「这块盘能用」的定义**。
2. 任何失败 → **把镜像摘掉，降级成 warning，引擎继续单盘跑**，
   和「盘拔了就回到单盘」是同一条规矩。**今天它是致命的，应该是降级的。**
3. 运行期再加一条：某个源连续 N 次 `ERROR_IO_DEVICE`（1117）或超时 → **动态摘源**，
   权重归零，`status.json` 记一行。`source_router` 已经是按权重选的，**把权重设成 0 就够了**。

### 5.3 如果 USB4 盒子还是死

那就轮到 #5 了，而且有一个干净的判别法：
**把这块 J.ZAO 插进机器的内置 M.2 槽（或另一台机器）再跑 §5.1 的四条臂。**
过了 = 盘没问题，是 USB 路径（任何 USB 路径）；不过 = 盘该换。
**在那之前不要给这块盘定罪，也不要给它平反。**

### 5.4 如果非用 USB 路径不可（不推荐）

本轮唯一**测到过能活**的形状是 D2 §1/§3 的：**1 个句柄、QD ≤ 8、4 MiB → 0.96 GB/s**。
**48 句柄 / QD 24 在 17 秒内必死。** 中间没有测过，所以：

> **不要写「QD ≤ N 就安全」。** 本轮没有测出任何一个在多句柄下安全的 QD。
> 能说的只有：**少句柄 + QD ≤ 8 活过，48 句柄 + QD 24 没活过。**

## 6. 结论

1. **`deepmoe` 是清白的。** 同样的 Win32 调用序列、没有引擎，17 秒复现。
   D2 §4 / §7 三次失败**不是代码问题，一次都不是**。
2. **`win32 1117` 落在 `norm.weight` 上是巧合。** 它只是桥咽气那一刻在飞的那个请求。
   `12 KiB` 小读**不是触发条件**——纯 4 MiB 就够了。
3. **凶手排第一的是 RTL9210 / UAS 桥**：复位先于 IO 失败、LBA 不重复、
   失败跟负载形状走。**SSD 排最后，但 SMART 没读到，所以不能宣判无罪。**
4. **USB4 盒子有很大机会修掉 #1，修不掉 #2/#3/#5。**
   所以到货之后**必须跑 §5.1 的验收门**，而不是 `ls` 一下就当好了。
5. **D2 §6「(b2) 这块 U 盘 —— 不要再试」一个字不改**，
   现在它后面多了一句：**连 `deepmoe` 不在场的时候都不要试。**
